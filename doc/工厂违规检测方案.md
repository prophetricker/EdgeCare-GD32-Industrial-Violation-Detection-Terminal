# GD32边缘计算赛题：“EdgeCare 慧眼智护”工业违规检测终端实施指南

## 一、 项目概述
本项目旨在基于 **GD32H7 (Cortex-M7)** 与 **GD32VW553 (Wi-Fi 6 + BLE)** 双芯架构，打造一款“隐私保护型多模态边缘智能终端”。
* **核心痛点**：高危车间/保密工厂需要监控违规操作（如未戴安全帽、闯入危险区），但传统视频流回传存在**商业机密泄露风险**且占用极大带宽；同时，云端推理延迟高，无法满足紧急停机的实时性要求。
* **初赛核心**：在MCU上部署TinyML视觉与音频模型，实现“**只传结构化报警数据，绝不传视频/音频流**”的边缘计算闭环，主打数据隐私与断网可用。
* **复赛升维**：引入外部NPU算力，部署轻量级视觉语言模型（VLM），从“单一违规检测”升级为“**复杂场景理解与自动生成巡检日志**”。

> **核心原则（针对不到20天的初赛）**：放弃花哨的UI和机械结构，死磕“模型量化部署”与“双芯通信稳定性”，用工业级的声光联动和抓包数据证明系统价值。

## 五、 20天冲刺实施指南（工业视觉避坑必看）

### 1. 模型量化与内存管理（初赛生死线）
* **痛点**：GD32H759 虽有 1MB SRAM，但系统、FreeRTOS、图像帧缓存（Framebuffer）会占用大量内存。留给神经网络权重和激活值的内存极度紧张。
* **策略**：
  * **图像降采样**：不要直接用 640x480 跑推理。在 H7 内部将图像缩放至 **96x96** 或 **128x128** 再送入模型。
  * **模型选择**：放弃复杂的 YOLO，初赛选择 **MobileNetV2 (0.35x)** 或 **MCUNet** 做图像分类（如：戴安全帽 vs 没戴），或者使用极简的 **Haar Cascades / HOG+SVM** 做人员检测。
  * **内存复用**：利用 H7 的 **TCM（紧耦合内存）** 存放模型权重，利用外部 SDRAM（如果开发板带）或内部大 Block SRAM 存放图像数据，通过 MPU（内存保护单元）严格划分。

### 2. 双芯协同与“隐私抓包”演示（拿分核心）
* **通信协议**：H7 与 VW553 之间使用自定义的轻量级二进制协议或极简 JSON。VW553 通过 MQTT 将数据发往云端。
* **演示设计（极其重要）**：
  * 在答辩现场，**打开 Wireshark 或路由器后台抓包**。
  * 当人员违规时，向评委展示抓包数据：网络中**只有几十字节的文本**（如 `{"dev":"01", "err":"no_helmet", "conf":0.95}`），**绝对没有视频流和音频流**。
  * 以此强力证明产品解决了“工业隐私泄露”和“带宽占用”两大痛点。

### 3. 光照与摄像头的“物理外挂”
* 工业车间光照复杂（逆光、频闪、暗角）。纯靠算法很难弥补物理光学的缺陷。
* **解决办法**：购买摄像头模块时，**务必买带“红外滤光片切换”和“高亮白光补光灯”的版本**。在代码中联动：当雷达检测到人，且环境光较暗时，H7 自动打开摄像头补光灯，确保 AI 识别率。

### 4. 毫米波雷达的“低功耗守门员”逻辑
* 不要让 H7 24小时不间断跑视觉推理，这不仅发热严重，且显得“不够边缘智能”。
* **正确逻辑**：
  1. H7 进入低功耗睡眠模式（Stop/Standby）。
  2. HLK-LD2410 毫米波雷达（功耗极低）持续监测。
  3. 雷达检测到“有人进入监控区域”，通过 GPIO 中断唤醒 H7。
  4. H7 启动摄像头，进行 3-5 秒的视觉推理。
  5. 推理结束且人离开后，H7 再次休眠。
  *在答辩时展示功耗仪上的电流波浪图，评委会非常认可这种工程化思维。*

## 六、 首周行动清单（Action Items）

- [ ] **Day 1**：采购核心板、OV5640摄像头、毫米波雷达、声光报警器及工业电源模块。
- [ ] **Day 1-2**：搭建 Keil/IAR 开发环境，移植 FreeRTOS。跑通 H7 的 DCMI 摄像头采集，并在电脑端通过串口打印图像数据（或写个简单的上位机查看画面），确保摄像头驱动无误。
- [ ] **Day 3-4**：在 PC 端使用 Python (PyTorch/TensorFlow) 训练或下载预训练的轻量级安全帽检测/人员入侵模型，使用 **TFLite Micro** 或 **NNoM** 进行 INT8 量化。
- [ ] **Day 5-6**：将量化后的 C 数组模型导入 H7，跑通纯 CPU 推理。使用 H7 的 CMSIS-DSP 库（特别是 ARM Cortex-M7 的 MAC 指令）优化卷积计算，提升帧率。
- [ ] **Day 7**：打通 H7 与 VW553 的 UART 通信，实现 VW553 连上 Wi-Fi 并将 H7 的虚拟报警数据发送至 MQTT 测试服务器（如 EMQX 公共测试服）。
